# 基于复用时间分布与边际重算收益的 KV 淘汰策略 v1

日期：2026-11-09。审核基线：`fb3d747`。状态：经源码／模型支持／历史决策复评分审核的设计建议，尚未接入原生控制器或执行新 GPU 实验。此次审核不改变任何已冻结实验、预测器或账本。

## 1. 审核结论

建议实施“前缀约束下的分布折现重算价值排序”，先作为KV驻留／淘汰策略，沿用FCFS请求执行。原建议方向成立，但应把未经估计的“未来仍驻留概率q(t)”改成明确定义的时间折现权重，并按可回收物理块的边际重算成本计价。

第一版仅支持压力触发、单块叶子淘汰。主比较先使用固定时间尺度，容量自适应单独作为后续消融；不把预测、时间尺度、请求排队规则同时改变。目标是降低真实端到端JCT，在线评分优化的是可解释的重算收益代理，不能声称JCT最优。

这个方向与仓库已有计划 `reports/mixed_workload_reuse_prediction_plan_2026-10-27.md` §5.1一致。使用分布加权本身不构成算法新颖性；需要证明在相同预测信息、后端和负载下，它比时间点排序及固定窗口策略产生更好的决策和JCT。

## 2. 当前实现与证据

`src/leasepath/predictive_cache.py` 的当前策略是：容量不足时，保护活动块和正在接纳的请求；只选择不破坏前缀连续性的叶子；先淘汰无存活owner的块，然后按 `max_owner F_U(3s)/block_bytes` 从小到大淘汰，平局按LRU、深度、key。预测支持不足时回退retired-first LRU。完整分布已由预测器生成，控制器只读取3秒处。

`src/leasepath/cache_matrix.py` 固定3秒horizon；`scripts/qwen_cache_resident_tree_batch.py` 按已观测就绪时间FCFS，模型执行串行、工具并行。当前 `is_queued`、`queue_length` 仍unknown，不能宣称已做队列感知预测。等待中的ready请求也没有独占保留资格。

最新完整自然轮为18批54/54正确：LRU平均JCT51.856秒、经验51.641秒、GBDT50.675秒。GBDT观测下降2.279%，但6轮有1轮反向，且工具耗时、部分协议输出token存在差异。它只支持继续研究，不能作为新策略应当达到的“保证下限”。

## 3. 原评分的审核问题及修订

| 问题 | 后果 | v1处理 |
|---|---|---|
| q(t)被称为“缓存保留到t的概率”，却没有估计方法 | 未来存活由当前和后续淘汰决定，直接用历史存活率会产生策略反馈／选择偏差 | 使用确定的时间折现 `w(t)=exp(-t/tau)`；不把它解释为估计概率 |
| 用整段前缀cold-prefill成本给每块计分 | 同一重算收益被重复计价，长前缀可能得到虚假高分 | 用“删该叶子前后”的边际prefill成本 |
| 把每个共享owner价值相加 | 一个物理块被重复计收益或占用 | 物理字节只计一次，owner价值取max代理，单列共享子集 |
| 用hU直接做区间概率 | 把风险集条件概率当无条件事件概率 | 使用 `Delta F_U(k)=F_U(r_k)-F_U(r_{k-1})` |
| 用工具完成时间代替lookup，或再次条件化已经是剩余时间的预测 | 忽略FCFS排队、重复扣除elapsed | 从当前快照预测剩余合法lookup时间，沿用U/D契约 |
| 将缓存占用率当唯一压力 | 缓存接近满载时所有决策压力近似相同 | v1固定tau；后续用本次真实缺口／可回收容量定义压力 |
| 直接优化预计命中tokens或把节省prefill等同JCT | 忽略边际计算成本、排队与任务重叠 | 主终点评估自然JCT，tokens／prefill只作解释指标 |
| 将分布尾部补成一定复用、把unsupported当零 | 人为确定未来且偏向淘汰缺数据会话 | 公共有限窗口、支持不足回退，不补尾、不把unknown当dead |

## 4. 输入与共同有限窗口

决策时刻t0只接收截至此刻的已观测状态。

- 每个idle owner：兼容ID、已观测前缀、工具／phase、elapsed，以及冻结预测器的分布。
- 物理状态：前缀树、活动引用、存活绑定、真实block bytes、本次请求已知token及需补块数。
- 代价表：同模型、同精度、同硬件和执行配置下，正式测试前独立校准的prefill耗时表。
- owner ID仅用于引用／共享聚合与日志，不是模型特征；未来工具结果、下一请求长度、未来到达、未来命中、真实剩余时间不进入决策。

定义 `F_U,i(t)` 为从当前快照起，t秒内先发生合法复用U的累计概率；`F_D,i(t)` 为先发生retire D的累计概率；`S_i(t)=1-F_U,i(t)-F_D,i(t)`。淘汰不改变真实需求标签；缺页仍是U。C只控制观测／训练mask，不是第三种竞争事件。

当前模型区间右端为0.01、0.03、0.1、0.3、1、3、10、30、60、120、300、600秒。训练风险集的workflow支持分别为40、40、40、40、40、38、13、6、4、2、2、0。

本次方案先规定共同评估上限 **H=30秒**，且所用各区间全局训练workflow支持至少5；初始折现尺度 **tau=10秒**。这是工程初值与数据支持门槛，非统计置信保证，也未通过JCT调优。30秒处只有6个训练workflow，仍需报告误差和回退率。H、tau及门槛在新轮运行前冻结，不能看新测试JCT再选择。

所有候选使用同一H，不能某个只积分到3秒、另一个积分到30秒再直接比较。H之后的U贡献不计入有限窗口目标，但剩余概率仍单列，不能重归一化成“30秒内一定发生U”，也不能标成D。若共同支持无法覆盖规定窗口，该次有存活绑定的候选比较统一回退原retired-first LRU。未知兼容ID和无效分布同样回退；非法概率／NaN要记录数据错误，不能进入排序。

现有elapsed分桶仅到1秒：超过1秒均落同一档，tool_elapsed_s也未直接被两种冻结模型使用。因此当前同tool／phase且elapsed均>1秒的会话可能有完全相同分布。频繁调用预测器不能自动产生动态剩余时间能力。扩充elapsed／队列特征属于之后独立的预测器实验，不与这次策略改动合并。

## 5. 推荐评分

对候选物理叶子块b、可合法复用它的idle owner集合O_b，定义：

`p_i,k = F_U,i(r_k) - F_U,i(r_{k-1})`，其中 `F_U,i(0)=0`。

`W_i = sum_{r_k <= H} exp(-r_k/tau) * p_i,k`。

`V_b = max_{i in O_b}(C_i,b * W_i) / B_b`。

评分高的优先保留；压力下淘汰最低分的合法叶子。

- B_b是释放这个物理块实际回收的字节。当前128tokens的F16块为33554432字节，即32MiB；同块大小时分母不改变排名，但保留单位和后续扩展含义。
- C_i,b是保留该块能避免的边际prefill耗时，单位秒；因此V是“折现的prefill秒／字节”代理。
- 使用区间右端点r_k作为权重，对真实区间内单调递减折现提供保守离散化；不假定区间内均匀分布。宽桶会损失精度，不能在看到结果后换成中点。
- D已通过竞争风险减少U概率，不再额外乘 `1-F_D`，避免重复惩罚。
- `max(C_i,b * W_i)`要在每个owner内先乘再取max，不能取 `max(C)*max(W)` 拼接不同owner。
- max保留当前共享聚合的保守工程思路，但不是精确“至少一个owner复用”的概率，也不是首次修复或多次复用收益的无偏估计。owner之间相关时不默认独立，不用 `1-product(1-F_i)` 自称真实联合分布。
- 没有存活owner的合法候选按已有规则优先淘汰；这表示当前没有绑定需求，不宣称未来新会话绝无共享复用。

例如同块大小、同边际重算成本，A在1／10／30秒对应区间的U质量为0.2／0.6／0，B为0.2／0／0.6，两者其余0.2不作未来判断。固定F_U(3s)均为0.2；上述W_A约0.402、W_B约0.211，新评分保留A。若B边际重算成本是A的2倍，B价值约0.422，又应保留B。此例只是算术说明，非实际测量。

## 6. 边际重算成本如何获得

不能用历史三策略的“总prefill时间／tokens”均值直接拟合策略专属成本，也不能把未来请求的真实长度用于当前评分。

使用正式实验前单独校准的 `T(P,h)`：在相同后端，已知总prompt长度P、命中前缀h时的实际prefill耗时，排除decode。测量覆盖预计使用的长度和命中组合，并包括原生批处理边界；测量重复、顺序交错，检查曲线与同配置的独立校准样本。拟合要求h增大时T不增，必要时做单调约束；原始噪声保留，不按最快值选成本。

对owner i当前已观察到的前缀长度P_i和当前最长驻留连续前缀l_i，删一个128token叶子时：

`C_i,b = T(P_i, l_i-128) - T(P_i,l_i)`。

这里P_i使用已观测的请求前缀作代理。未知的未来工具返回／新增后缀不填真值；该估计未必等于未来完整请求的真实边际耗时，要单列校准误差。删除叶子后l_i变化，后续新暴露叶子的C必须重算。实现校准表要区分固定开销与随缓存长度变化的开销，避免将整次请求固定开销重复分摊到每块。

如果尚无合格成本表，先让全部候选C相同，明确标为“仅分布评分”。任一当前候选需要的成本超出校准支持，该次所有候选都用相同常数作成本回退，不能有的候选用秒、有的用tokens。回退记录单独统计，不能称该次验证了成本感知收益。

等大小块且C近似常数时，V退化为W排序；若所有分布也近似相同，新算法就接近原LRU。这是需要测量的退化情况，不应强行制造分数差。

## 7. 完整决策流程

请求执行顺序沿用FCFS；此策略管理GPU KV驻留与淘汰，不进行CPU卸载、预取或请求重排。

1. 完成兼容性、请求长度、活动容量与headroom检查。活动容量不足按原行为等待／失败返回，先保持状态原子性。
2. 当前实际接纳请求需要的前缀及所有活动引用不可淘汰。已经ready但尚未接纳的请求不新增硬保留权，避免挡住当前就绪工作。
3. 没有真实容量缺口时不预测、不驱逐；保留缓存至下一次压力。
4. 枚举当前合法叶子；其中无存活owner的块先按原LRU规则淘汰。每删一块都更新树，不能只看最初的叶子集。
5. 如仍有缺口，对存活候选所需owner在同一个t0构造快照，每个owner预测一次，计算W。预测器参数及特征白名单保持冻结。
6. 所有存活候选满足共同窗口支持则计算V；支持不合格统一回退retired-first LRU。成本缺支持则统一使用常数成本。
7. 选择最低V叶子；完全相同分数按原 `touched, -depth, key` 决定。删除真实native cells，并更新绑定可达前缀、共享引用、可回收集合及边际成本。
8. 重复直到恰好满足本次缺口。新增候选若引入无预测支持的owner，后续剩余决策进入统一回退并记录；已经执行的动作保留。
9. 生成、idle、工具状态变化、retire、取消、超时和恢复沿用原生命周期检查。退役一个owner不能删除其他owner仍引用的物理共享块。

这是一种带前缀约束的贪心启发式，不是全局最优缓存配置求解器。可变大小片段、整子树淘汰、多个互补前缀的组合价值另作后续工作；本版以单块叶子为单位避免错误计价。

同一次接纳的评分使用同一t0／tau／分布快照，避免删块时钟推进造成自相矛盾。状态变更时使预测缓存失效，下一次压力时按当前elapsed重算；不必每个decode token重复预测。

## 8. 容量压力适配作为独立版本

第一版固定tau=10，便于判断完整分布本身有无价值。不能将新τ与原固定3秒策略混称同一实验。

后续可以加入只依赖当前状态的压力折现：

`rho = 本次还缺的物理块数 / 当前可按合法叶子顺序回收的全部idle块数`。

`tau(rho) = clip(tau0/(1+alpha*rho), tau_min, tau_max)`。

分母是可回收块总量，包含之后才暴露的叶子，不是当前叶子个数；当前接纳前缀／活动块全部排除。有效可接纳状态下rho位于(0,1]，分母为0则不能靠评分解决容量不足。

一个待验证工程初值是tau0=10秒、alpha=1、tau_min=3秒、tau_max=30秒，因rho范围其实际tau在5–10秒。参数要单独冻结；不是已知最优值。压力越大越强调近期复用；同次接纳中rho只在动作开始前计算一次。它仍是折现权重，不是对未来驻留概率的估计。

由于实际缺口受当前缓存状态影响，这个自适应策略仍存在闭环反馈，必须重新跑真实闭环。不能用旧策略记录的未来淘汰时间或未来分配速率作为q(t)，也不能把旧日志重评分当新轨迹的收益。

执行 `scripts/audit_kv_distribution_proposal.py`，从最终自然轮提取48个有预测记录的压力状态，将同一组状态分别交给两种冻结模型；只用当前已记录特征，恢复当时兼容域映射。按H=30、tau=10、区间右端折现、相同成本重新计分。84个历史F_U(3s)值与已记录结果一致。

| 冻结预测器 | 状态数 | 可比较idle owner对 | 相对F_U(3s)发生顺序／平局变化 |
|---|---:|---:|---:|
| 条件经验 | 48 | 36 | 0 |
| GBDT | 48 | 36 | 2 |

数据位于 `results/cache_policy/kv_distribution_strategy_review_2026-11-09/score-audit.json`。这是针对已查看开发轨迹的方案诊断，不包含未来标签、拟合或模型生成。候选owner对不一定对应当前可淘汰物理叶子对，因此2次顺序变化不等于2次真实淘汰变化；没有模拟新缓存路径，也没有产生新的tokens／prefill／JCT收益。

结论：当前数据上，单纯把一个CDF点换成分布加权可能只改变少量排序。边际成本是否有足够差异、候选分布是否交叉、未来更多工具与循环是否形成不同等待模式，才决定它是否有实际空间。H／tau不是根据这2次变化调整出来的，也不能挑选“变化最大”的参数当最终方案。

## 10. 对照设计与实施顺序

先固定一个预测器（建议沿用GBDT）比较策略，再将有价值的策略复制到经验模型检查；二者始终使用同一已观测信息，分别回答预测与决策问题。

| 组 | 评分／规则 | 识别的因素 |
|---|---|---|
| A | retired-first LRU | 强基线 |
| B | 当前F_U(3s)，同成本 | 已有方案 |
| C | W_i，H30／tau10，同成本 | 完整分布折现 |
| D | C_i,b*W_i/B_b，固定tau | 边际重算成本 |
| E（后续） | D加当前压力tau(rho) | 容量适配 |
| T（机制对照） | 同预测分布导出的有限窗口剩余时间排序 | 压缩成一个时间值是否足够 |

T可用 `sum r_k*p_i,k + H*(1-F_U,i(H))` 作为“截至H仍无U记为H”的有界下一次需求时间，较大者先淘汰。D事件在此有界U目标下同样记H；明确这是有限窗口机制对照，不能称为CacheWise完整复现，也不能把它写成无条件真实均值。若做原论文对照，需要另行实现参数TF-IDF／KMeans、条件剩余时间与更新机制，并核对信息可用性和原论文设置。

具体实施顺序：

1. 实现版本化评分器和证据字段，通过真实前缀／共享块／物理容量约束的单元与原生检查。已冻结旧源文件及结果保留。
2. 单独完成T(P,h)成本校准并冻结表、训练支持、模型、H／tau。先做B／C同成本消融；若合法受害块基本不变，报告无明显决策空间，不以完整GPU矩阵掩盖。
3. 对A／B／C／D运行新的完整策略平衡交叉顺序；四策略不能照搬原三策略六种排列，使用事前固定的平衡设计并报告顺序覆盖。输入、参数、模型FCFS、真实工具、控制开销和驻留控制一致。
4. 保留每次同状态shadow LRU及原F_U(3s)的受害块比较。影子策略只作动作解释，不根据影子历史外推JCT；所有策略承担相同审核开销。
5. 主终点平均任务JCT；同时报告整批完成时间、逐轮／逐题差值、尾延迟、实际prefill tokens与时间、decode及输出token差异、工具各阶段、预测与决策耗时、GPU／主机协变量、所有失败与回退。
6. 先在当前24块／3会话开发单元验证机制；扩容并发及新的独立母题／真实agent循环验证泛化。当前50母题与40/10划分均已经查看，不重新包装成独立最终测试。

需要的边界检查至少包括：F_U相同单点但分布不同、所有预测同分退化为LRU、零概率／尾部缺支持、D竞争风险、共享owner退役、叶子逐块变成祖先、非法前缀／容量原子失败、成本越界统一回退、同次t0固定、分布缓存失效、硬活动保护及取消／恢复。

## 11. 日志与验收

每次压力记录策略版本、模型／成本表哈希、决策时刻、H／tau、完整分布支持、区间质量、W、C、真实字节、owner聚合、候选叶子、排序元组、回退理由、实际被删native cells，以及同状态旧策略的候选动作。日志只保留已知值，真实后续事件独立写入审计流。

验收分三层：

- 正确性：最终答案／协议及原生KV证据全通过，容量与共享前缀约束无违反；任何失败保留并按预先规则停止。
- 局部机制：新增评分确实改变合法动作；进一步在新闭环中观察命中与prefill收益，扣除新增预测／决策开销。只改owner排序而没改动作不算收益。
- 端到端：完整配对JCT改善，报告反向轮次和不确定性；轮次与母题分别作为相关性单位，不能把同一母题多轮当独立样本夸大显著性。JCT不改善则不把“命中更多”宣布为完成目标。

沿用已验证的Python／系统／execve+shebang依赖驻留与工具进程树计数。上一轮控制器4KiB读取仍未定位；新轮应先补控制器完整读取／子进程归因，并前瞻声明父进程门控，不能事后放宽成协变量。共享CPU及内存带宽不独占，持续记录，不声称全局主机稳定。

本设计优先完成“预测分布→合法淘汰→prefill改善→JCT改善”的证据链；请求优先级、硬租约、迁移预取和重新训练分别在后续独立版本中评价。
