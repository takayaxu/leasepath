# LeasePath：持续 Agent 结果后的补实验计划

版本：2026-11-11。依据已完成的六项目、五策略真实 KV 开发对照。本文登记后续设计与验收条件，不表示这些实验已经运行，也不改变当前冻结评分或历史原始记录。

关联：[新版论文](leasepath_isca2027_paper_v2_2026-11-11.tex)、[新版大纲](leasepath_iclr_outline_v2_2026-11-11.md)、[本轮报告](../reports/continuous_e2e_development_2026-11-11.md)、[完整工作流](../test_workflow.md)。

## 1. 当前决策

保留**等成本分布评分**作为共同缓存决策接口，继续固定 H=30 秒、τ=10 秒、成本乘数 1、max-owner、全窗口至少 5 项目风险支持、仅压力下合法叶淘汰、retired-first LRU 回退和 FCFS。预测器选择、静态/动态更新与可能的混合方式暂不定型。

固定评分不等于固定旧预测器。新数据需要训练目标域预测器；预测输入、模型、更新规则各自版本化。旧基线 manifest 的 `retraining=false` 是历史身份，不能用来禁止新实验的因果更新，也不能把新预测器写成同一个冻结模型。

本轮五臂说明预测策略在已知持续项目上有实际端到端收益，但不能选择最终赢家：

| 对照 | 已有观察 | 尚不能推出 |
|---|---|---|
| 动态 GBDT 分布 vs LRU | 多复用 329,344 tokens；prefill 少 718.835 秒；平均轮次响应少 77.927 秒 | 跨项目泛化、统计显著或各种负载均有效 |
| 动态 vs 静态 GBDT 分布 | 多复用 4,096 tokens；平均响应低约 0.20% | 在线更新有稳定额外收益 |
| 动态分布 vs 动态 3 秒窗口 | 多复用 896 tokens；平均响应反而高约 0.04% | 分布评分优于固定窗口 |
| 动态经验分布 vs GBDT | 经验策略本轮响应较慢；各自都优于 LRU | 模型复杂度越高越好；经验分布不适用 |

五臂都是同一批六个开发项目；初始训练已经使用这些项目的完整采集轨迹，再在相同需求上运行端到端。在线更新截止点没有使用未来标签，但这不把已知项目评估变成未见项目评估。

## 2. 优先顺序与最小交付

| 优先级 | 实验 | 回答的问题 | 最小产物 |
|---|---|---|---|
| P0 / E10 | 当前五臂平衡重复 | 大幅相对 LRU 收益是否复现，近似平局是否只是波动 | 至少 5 个位置平衡周期、完整时间分解、项目/周期配对差异 |
| P0 / D7 | 扩展独立持续项目 | 避免重复同六题与训练轨迹熟悉度解释全部收益 | 来源表、按组划分清单、能力试点与失败归档、合格采集 |
| P1 / E11 | 预测器×更新×评分的分离消融 | 分布、预测器与更新各贡献多少 | 静态共同 checkpoint 评分对照；缺失实验臂补齐 |
| P1 / E12 | 新负载的容量/并发矩阵 | 竞争强弱、饱和与无收益边界 | 可行性预检、9 个矩阵单元的质量与响应结果 |
| P1 / E13 | 稳态/漂移与在线预测 | 什么情况下需要动态、混合是否值得 | prequential 指标、更新前后曲线、含开销的自然 E2E |
| P2 / E14 | 外部方法与后端 | 与现有方法的关系是否成立 | 忠实复现说明、同信息对照与完整系统结果分开 |
| P2 / D8 / E15 | 生命周期与长尾 | 当前全 U 快照之外的预测是否有效 | 自然 D/C、长工具/用户返回覆盖与分层指标 |

先做 E10 与开发数据能力试点。E11 在开发集合冻结后进行；E12 不在每个单元穷举所有候选。最终留出只运行预先选定的主方法、LRU 和关键强对照，不再据其结果改模型。

## 3. E10：同配置平衡重复，优先补可信度

当前顺序 LRU → 经验动态分布 → GBDT 静态分布 → GBDT 动态窗口 → GBDT 动态分布，不能排除时间/温度/主机状态与策略绑定。把已有一周期保留为探索结果，不事后并入预登记的确认周期。

冻结代码、项目、用户序列、思考时间、初始模型与缓存起始状态。每臂都从相同初始预测器独立开始，在线学习只使用本臂之前的已观测数据，不跨臂、跨周期积累。模型加载与驻留准备单列；稳态用户响应照常包含控制器、验证及后台训练影响。

五策略记为 A=LRU、B=经验动态分布、C=GBDT 静态分布、D=GBDT 动态窗口、E=GBDT 动态分布。最小五周期采用：

| 周期 | 顺序 |
|---|---|
| 1 | A B E C D |
| 2 | B C A D E |
| 3 | C D B E A |
| 4 | D E C A B |
| 5 | E A D B C |

每策略各占每个位置一次。五周期本身**不**平衡全部有向相邻对；若要报告一阶前序平衡，加上这五序列各自逆序，登记为十周期 Williams 设计，不能把五周期称为完整前序平衡。

按当前每臂约 49–61 分钟服务时间，25 臂约需 22 小时量级，另计加载/预检；不是完成时间承诺。逐臂实时记录进度，周期结束生成审计。持续资源失败应停止该确认版本并保留分母，修复另起版本；不能删除慢批次或仅补跑不利样本。

共享主机保持相同 CPU affinity、数值线程、NUMA/THP、模型及依赖驻留、工具文件/临时目录方式。记录 GPU 利用率/温度/功率、CPU/I/O/内存压力、父子 major fault/read bytes 和加载时间。门槛提前冻结，不以 JCT 数值触发排除。账号不能约束其他任务，故结果只能称共享服务器条件下的平衡配对观测。

统计以项目与周期为相关单位，48 个轮次不作独立样本。报告周期配对响应比/差、每项目差异、所有观察点和跨周期区间；仅六个项目时同时报告不确定性与有限样本边界。不能直接对全部快照或轮次做独立 t 检验。零或负收益同样进入结果。

## 4. D7：扩大真实持续项目，先保证来源与能力

沿用 `test_workflow.md` 至少 60 项目、每项目 8–12 用户轮次的目标，建议 36 训练、12 开发、12 密封评估。先按来源/仓库/模板/数据生成程序分组再划分；组不能跨集合。若实际来源组不足以满足数量，调整实例数并说明，不能随机拆派生版本凑独立性。

当前六个项目及其变体只算开发来源。旧 50 题及衍生题排除；原有六个留出来源族继续密封。外部仓库/公开任务需固定来源版本与使用许可。新增自行编写项目如实标为 authored，与独立获取的来源分别统计。

覆盖小代码仓库维护、数据与 SQL、运行故障/日志、API/配置集成、数值实验、文档/产物维护。项目应产生自然的多次往返、多工具组合、修订或分支，模型自行决定工具和停止。固定用户需求与到达规则，只揭示当前轮；不规定必须调用几次工具或必须失败。

补充有实际作用的较长计算、较大输入、文件/查询规模差异和用户返回间隔。工具时间来自真实工作，不能用 sleep 假装计算。固定用户思考时间可以是用户到达模型，但必须与工具时间分开，并报告自然 trace 与预设到达模式的区别。

先做开发能力试点，按既有预算与标准验收：轮次通过率至少 90%，每项目至少 80%，无未解决协议或反馈链错误。每个失败定位首错，区分环境/控制器、工具契约、规格歧义、数值算法、能力与容量问题。修复版本保留旧失败；正式阶段不得临时为某项目加预算或用参考答案纠正模型。

每个项目交付源材料、独立验收、来源组、实际工具日志、完整 prompt/token、U/D/C、episode/snapshot、分阶段时长及失败记录。公共检查验证行为/不变量，独立终验保存参考；不把隐含正确数值塞进工具反馈。只增加快照数不算增加独立覆盖。

## 5. E11：把三个决策轴分开

目前五臂不是完全交叉设计：经验分布只有动态分布臂，缺经验静态等对照。开发阶段补成下表；每个预测器族的静态/动态臂从同一初始拟合开始：

| 预测器 | 静态 F_U(3s) | 静态分布 | 动态 F_U(3s) | 动态分布 |
|---|---|---|---|---|
| 条件经验 | 待补 | 待补 | 待补 | 已有探索一臂 |
| GBDT | 待补 | 已有探索一臂 | 已有探索一臂 | 已有探索一臂 |

另加 retired-first LRU，共 9 臂。预算不足可先补 GBDT 静态窗口和经验静态分布，得到同 checkpoint 的评分对照和同评分的更新对照；不把缺失格子的效果推断为已测。

**评分效应主对照：** 同一静态模型、相同特征/初始状态/可行域，对比 F_U(3s) 与 H30/τ10 分布。记录支持掩码与回退。旧窗口实现只检查自身窗口支持，分布还检查全 H 风险支持；另设显式“共同支持门控”消融，才能区分信息积分与门槛差异。不能悄改既有基线。

**更新效应主对照：** 同一预测族/评分/初始模型，比较静态与固定成熟门槛动态。自然运行中动作改变到达和标签时间，后续动态模型轨迹可以不同；“同初始模型”不能写成“始终使用相同预测”。

**预测器效应：** 相同训练来源、因果特征允许表、成熟规则、支持口径与评分，比较经验和 GBDT，报告各自耗时。工具名保留；删除工具名只作可选消融。已知参数规模/工具类型尚未全部实现，须先独立版本验收再测试，不改写当前结果。

保留静态模型上的同状态只读回放：比较合法受害块、排序分歧、存活到真实 lookup 的 token；它是机制诊断，不能替代自然 E2E。选真实存在的“窗口概率接近、远端质量不同”案例，不用构造示例充当实测收益。

## 6. E12：针对新历史长度登记容量/并发

旧 24/32/64 块无法容纳当前完整单请求历史，不能继续用于新负载的主压力矩阵，否则测成准入失败。新矩阵先做仅资源/合法性预检，再在看性能结果前登记。

当前六项目的候选为 **150/192/224 块 × 3/6/10 并发**，对应持久 KV payload 4.6875/6/7 GiB，非最终通用参数。保留 32K context、2048-token transient headroom、每块 128 token/32 MiB；真实 CUDA 预分配字节另报。

扩展项目可能超过该范围。必须按所有策略共同的最长合法完整请求、生成预算及 native 临时空间确认下界和总资源；不合格则在正式测试前调整全矩阵或另设公开上下文管理规则。不得看某策略收益后改容量，或仅为一种策略截断历史。

9 个单元先对比 LRU、同 checkpoint 静态窗口、静态分布，以隔离评分；动态收益在 E13 单列，再将开发阶段选定动态/混合候选带入关键单元。高容量可能不竞争，低容量可能过载，两者都保留。

每单元使用相同项目池/需求/固定到达规则，负载分配预先登记。若 3 并发只跑 3 个项目，当前“至少 5 个已观测项目”门槛可能根本不更新；应使用跨服务波次的项目流且至少覆盖 5 个不同项目，保持并发上限为 3。不得为产生更新偷偷降低门槛。必须报告实际部署次数及触发/跳过原因。

报告实际 payload 占用、合法候选、保护阻塞、淘汰 token、命中/预填 token、prefill/queue/response、吞吐、质量与超时。10 并发必须承认模型串行服务与排队，不能写成 10 路模型并行。到达率过载与缓存不足分别诊断。

## 7. E13：静态、动态及混合在何时有效

先按时间顺序构建稳定项目流与真实分布改变项目流。漂移来自有意义的工具/参数规模、主题/输入、上下文长度或用户到达混合变化，提前登记切换；不通过改日志时间或工具 sleep 制造效果。至少包含对训练相近的稳定段和未参与拟合的改变段。

比较静态、当前固定成熟门槛动态、可选漂移触发动态。动态规则、训练窗口/回放比例、最小支持、更新 CPU 预算在开发阶段登记并冻结。先测持续累积是否足够，再测滑窗/衰减，避免一次引入多种变化。

在线预测必须先发出预测再评分，待事件成熟后更新，保存模型版本与 cutoff。记录各 horizon 的需求 Brier、校准、分层排序损失、支持/回退率和样本事件构成；删失用完整可观察区间，不能把未返回一律当负样本。评估未见项目适配时，初始模型不包含该项目采集轨迹；允许同项目先前轮次的成熟信息，未来信息不进入模型。

**混合仅为候选。** 一个概率有效的起点是对每个区间的风险向量作凸组合：

`h_mix(k|x) = α(x)·h_GBDT(k|x) + (1−α(x))·h_emp(k|x)`，`0≤α≤1`。

对 U/D/等待三类一起混合后，按同一 survival 递推得到累计发生率，再送入冻结分布评分；不能分别任意混合每个 horizon 而破坏单调性和总质量。先测试一个全局固定 α，再考虑基于已有支持量/历史 prequential 误差的门控。未知工具保留状态与回退，不能用未来校准误差选择专家。

α 与门控训练只使用已观测成熟开发数据；最终密封项目不调权重。混合如果没有在独立开发项目上产生超过开销的稳定收益，就保留较简单的静态/经验方案。不能因本轮三种 GBDT 接近就推断混合会更好。

## 8. E14/E15：外部对照、生命周期与系统边界

固定窗口不是 CacheWise：前者是 F_U(3s)，后者要按论文的条件剩余时间和排序实现。TTL、条件均值/分位数排序、生命周期基线及完整先前系统，分别说明信息量、调度、prefetch/offload 等差异。首先在相同后端/特征/合法动作下比较决策机制；完整系统比较另表，不能宣称复现了被省略模块的系统。

目前实际工具总耗时约 20 秒/臂、queue 快照占比约 77.5%，长工具覆盖不足。新增真实计算/查询/本地服务工作量和有依据的用户返回 trace。任务闭环需有自然终止、取消或上下文替换等真实生命周期，并在有其他请求产生决策时观察其风险，不能仅在日志末尾补 D 来假装模型训练有 D。自然观察窗口结束记 C，不能用丢日志或删样本凑删失。

补至少一个不同模型/规模或支持 continuous batching 的后端作为外部有效性验证。它不属于当前已完成证据；先确认兼容性与实际 KV 动作，再比较性能。

## 9. 统一终点、统计与完成条件

主终点为用户消息真实到达到独立验收交付的响应；完整项目 JCT/makespan、p50/p95、吞吐同时报告。固定用户思考不计入该轮响应，计入项目 makespan。失败/超时的分母、时间预算和处理规则提前登记；仅成功样本均值单列，不能把失败排除后作为全部工作收益。

每个实验至少交付：来源/划分/版本清单、冻结配置与代码哈希、prompt/feedback/token 一致性、物理 KV 审计、在线 cutoff 复演、质量分母、分层耗时、资源轨迹和原始失败。`cached + executed prefill = actual input` 逐请求核验；若生成/提示轨迹不同，如实报告，不能为了匹配 token 强改 Agent。

时长分别列模型加载、初始训练、预测、特征准备/调度、在线训练 wall/CPU、prefill、decode、工具、排队、验证。在线后台影响已在自然响应中；累积工具/训练会重叠，不能相加重建关键路径，也不能将 preparation 与其包含的 prediction 重复计费。

论文进入独立主结果阶段的条件：完成来源分离与未见项目评估；平衡重复支持主效应；评分与更新增益有各自消融；报告质量与全部开销；外部对照可核验。如果分布/动态增益不成立，主张缩小为可审计的预测保留接口与适用边界，不通过换指标掩盖。

## 10. 下一项具体工作

建立版本化的 E10 五臂重复登记与 D7 来源清单，复用当前已审计的控制器，先确认无新增完整性问题。持续开发采集的公开检查与独立终验同步审核；新预测特征另立版本。当前论文已可并行写作，缺失实验使用本文件 E10–E15、D7–D8 编号占位，不预填趋势。
