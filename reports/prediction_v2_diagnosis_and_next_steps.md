# 数据与训练 v2 诊断：是否继续使用 GBDT

2026-10-31。建议把条件经验预测器作为当前主方案，GBDT 保留为待验证候选。项目最终要验证状态条件预测能否改善 KV 决策；条件经验本身就是从数据学习的概率模型，没有必要为了采用 GBDT 而持续调参。

本次仅加载冻结模型、数据及折外预测，分析训练内误差、编码状态、树参数尺度和未使用的信号，未重训或调整参数。机器结果见 [diagnostics.json](../results/prediction/prediction_v2_diagnosis/diagnostics.json)，分析入口为 `scripts/analyze_prediction_v2.py`。

## 当前取舍

完整集 0.1 秒 Brier 为全局经验 0.4986、条件经验 0.3889、GBDT 0.4317。条件经验相对全局降低约 **22.0%**，当前 GBDT 相对条件经验的误差增加约 **11.0%**。质量子集排名相同，失败执行不是主要解释；完整集 50 个母题各自的主指标也都是条件经验更低。

本机保存的单次 API 预测中位数约为条件经验 0.075 ms、GBDT 0.517 ms，约 6.9 倍。这不是完整在线开销，但目前没有整体预测优势来补偿额外成本。条件经验相对全局的改善证明当前状态含有预测信息，尚不能证明缓存收益；Brier 也不是百分比准确率。

## 输入实际上是一张很小的离散表

| 范围 | 快照数 | 编码后的状态组合 | 已观测状态×风险区间组合 |
|---|---:|---:|---:|
| 完整集 | 2,414 | **19** | **70** |
| 质量子集 | 1,553 | **16** | **61** |

实际学习输入只有 `tool_name`、`phase`、elapsed 桶及区间序号。工具只有 bash/unknown，phase 只有 waiting_tool/queued/unknown，elapsed ≥1 秒又全部归入同一桶。新增 34 个母题并未给模型提供 34 种任务语义。

条件经验直接为各状态、各区间统计 U/D/waiting，再收缩和回退。在这个小离散空间里，它能直接表达单元差异。GBDT 的跨状态共享和连续变量建模优势尚未发挥，浅树平滑可能增加偏差。条件经验不应被理解为完全没有表达能力的简单平均。

所有 idle-start 样本更是只有 **1 种编码状态**。完整集 idle-start 的 0.1 秒 Brier 为全局 0.5136、条件 0.5159、GBDT 0.5130。当前输入没有给它们多少区分任务的机会，单纯换模型不能恢复缺失信息。

## 训练内也较差，支持欠拟合诊断

| 视图 / 模型 | 训练内 0.1 秒 Brier | 折外 0.1 秒 Brier |
|---|---:|---:|
| 完整集 / 条件经验 | 0.3804 | 0.3889 |
| 完整集 / GBDT | 0.4300 | 0.4317 |
| 质量子集 / 条件经验 | 0.3922 | 0.4027 |
| 质量子集 / GBDT | 0.4403 | 0.4440 |

GBDT 训练内就明显落后，训练内到折外差距又很小。这更符合当前表示、容量或正则约束造成的欠拟合，不支持把主要原因解释成过拟合。训练内数字仅用于诊断；全量模型比各折使用更多训练母题，这不是严格的偏差—方差分解。

也不能只归咎于训练损失和 Brier 不一致：相同训练风险行及权重上的交叉熵数据项，完整集条件经验 **0.4037**、GBDT **0.6381**；质量子集为 **0.3987 / 0.6565**。GBDT 在自身目标对应的数据拟合项上也较差。

需要检查的约束包括深度 2、最多 4 叶、40 轮、学习率 0.05、L2=10。快照已按 workflow 归一，完整集 7,051 行风险记录的权重和为 163.99；这只是归一化尺度，不是独立样本数。完整集树叶 Hessian 中位数约 10.43，质量子集约 8.71，与 L2=10 同量级，惩罚并不小。浅树还要同时区分风险区间、phase 和 elapsed。

现有证据支持做一次受控容量/正则诊断，尚不能断言单改 L2 就会反超。完整集 0.1 秒的 2,414 份 GBDT 折外预测均来自树本体，未触发未知状态回退，因此差距也不是主要由 fallback 引起。

## 已有强信号没有进入训练

同一个旧编码状态 `bash + waiting_tool + elapsed<0.03s`，按快照时已知命令类别分组：

| 当前类别 | 快照数 | 剩余时间中位数 | 0.1 秒后仍等待 |
|---|---:|---:|---:|
| 检查 inspect | 92 | 0.0398 秒 | 0 / 92 |
| 编辑 edit | 155 | 0.0433 秒 | 0 / 155 |
| 测试 test | 123 | 0.5353 秒 | **123 / 123** |

命令类别已被采集，但原模型只看到 bash。在同一训练折中，它们必须为同一编码状态给出同样分布，无法分辨快速编辑和较慢 pytest。上表是相关快照的描述性事实，不是增强模型的独立测试成绩。

优先补当前命令类别、工具运行/结束状态和时间表示；之后分组加入已完成工具耗时/返回码、历史失败、可见工作量及单位、明确重试。当前命令只能在 tool start 后使用，不能倒填到更早的 idle-start；后者可以使用此前已完成工具的历史。未来工具总耗时、最终正确性及未来 lookup 仍禁止进入输入。

rows/bytes/test_cases 不能作为同一种规模直接比较。过细的 workload_family 可能近似母题 ID，需要检查跨母题可复用语义。新增信息必须同时给条件经验和 GBDT，前者使用合理的分层回退与收缩；只让树看更多信息后胜过旧经验表，不能证明树模型本身更优。

## 时长和评测覆盖仍薄弱

50 个母题中 44 个来自 MBPP；472 个 episode 中 **452 个不足 1 秒（95.8%）**，1–3 秒只有 6 个、3–10 秒只有 14 个。3–10 秒来自 3 个母题，质量子集仅剩 2 个。采集的可审计性较好，独立时间场景还不够丰富。

大量任务重复检查、编辑、pytest、提交的固定链路，当前学到的相当部分规律属于这个 runner 和本机工具环境。65 个 D 均来自显式关闭，其 episode 最长约 0.044 秒；多样的真实取消/上下文关系终止仍未覆盖。自然 C=0 限制删失情形检验，不是本次胜负的直接解释。

全部设计文件母题恰好落在第 3/4 折，质量子集两个长时段母题都在第 3 折，导致该折 10 秒无训练支持。它限制长时段结论，但解释不了 0.1 秒差距：0.1 秒三模型有相同的完整评分覆盖，训练内也已经出现差距。

GBDT 在当前已等待 ≥1 秒的完整集快照上有优势：0.1 秒 Brier **0.3930 vs 条件经验 0.4877**。但只有 126 张快照、6 个母题，它提示调查方向，不足以支持全局换模型。

## 推进顺序与停止条件

1. **条件经验成为当前主预测器。** 保留全局经验作为对照，沿用 U/D/继续等待接口。原训练 v2 继续作为冻结历史结果。
2. **做一次有边界的诊断轮，先 review。** 用旧输入检查一个事先规定、容量更充足的 GBDT 设置；另比较增强条件经验与获得相同信息的 GBDT，第一批只增加命令类别、工具状态和时间表示。分别识别容量与信息增量，不一次改变数据、输入、参数和划分。现有折外结果已用于分析，后续模型选择应在新冻结任务/时间留出上确认。
3. **新增采集优先扩大独立秒级母题。** 可先以 10–20 个独立秒级任务定义为工作目标，覆盖不同操作、规模和真实重试；这个数量不是统计充分性的保证。同母题多规模仍同组。下一版评测预先平衡已知来源/工作负载类型，补足各折长时段支持，不按当前成绩重新划分旧折。
4. **用条件经验推进最小 KV 决策闭环。** 明确哪些对象可淘汰、何时预测/更新、哪些 horizon 影响实际保留决策。已知待服务请求及活动对象优先用保护规则，queued 单独报告，重点评测真实可决策状态。在有容量竞争的受控实测中，对照 LRU、固定 TTL，以及同一决策器下的全局/条件预测，记录重算 prefill、miss、KV 占用、完成时间和完整开销。策略会改变时序，应分别真实运行，不能将固定时间线回放差异直接当作线上收益。

采用 GBDT 的条件应事先约定：在独立留出上相对获得同样信息的条件基线有稳定、具有实际意义的预测或决策收益，并能补偿额外开销。若受控诊断和独立验证后仍无增量，就停止将 GBDT 作为主线，使用条件经验推进系统。研究结论可以是可追溯的状态条件竞争风险预测改善 KV 决策，不要求某一类树模型必须胜出。

本次未执行上述后续训练、采集或策略实验；这些是推进建议。原 [训练 v2 Review](prediction_v2_50parents_review.md) 和数据/模型结果保持原版本。
