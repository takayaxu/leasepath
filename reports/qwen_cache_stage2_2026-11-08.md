# 真实多会话 KV 与端到端系统验收

2026-11-08（Asia/Shanghai）。承接 `qwen_cache_stage1_2026-11-08.md`，本阶段将元数据缓存控制器接到同一固定 Qwen2.5-Coder-32B F16 的原生 CUDA KV，运行真实工具与真实生成。

## 实现与物理验收

新增 `native/qwen_cache_cuda.cpp` 和 `qwen_cache_backend.py`。复用固定 llama.cpp `fd27b2034905f8dadd8bd6d2cc44595f4929d391` 的 dense F16 GPU KV；单执行序列 0 服务模型请求，序列 1–32 持有完整输入前缀块。`seq_cp` 增加同一设备 cell 的引用，不进行主机保存／恢复或构造预热请求。多个 owner 通过同一块键共享一个物理块，Python 控制器维护 owner 的关系与活跃状态。

当控制器选定叶块淘汰时，原生 `seq_rm` 删除持久引用，最后一个引用消失后 used cell 回到可分配池。正在执行的序列不被淘汰；异常清理只排空当前执行序列，未完成的新块不发布为持久缓存。Python 删除对应未物化元数据，其他 owner 仍可继续使用原有前缀。致命 adapter 异常则显式清空整个实验池并重置元数据，拒绝带伪状态继续执行。

本轮固定逻辑容量 32×128=4,096 tokens；按该模型的 KV 几何约 1GiB。额外活动输入尾部／生成 headroom 为 2,048 tokens，约 512MiB；逐次 peak 实际并集不得超过两者之和。原生 context 16,384 cells，**预留 GPU KV 缓冲总计 4GiB**，各逻辑策略相同：CUDA0/1 各 1,476,395,008 bytes，CUDA2 为 1,342,177,280 bytes。淘汰降低可复用 payload 和 used cells，不声称 CUDA 预留内存随块逐次缩小。

独立检查依据实际 `seq_pos_get`、cell ID 和 token 记录，核对所有序列并集等于 `get_used()`、块位置／token 与预期一致、活动／空闲配额、复用 cell 不变以及请求结束无 sequence 0 残留。不是根据客户端历史伪造物理 token 对应。

13 次真实受控生成通过：A 冷请求 1,372 个 prefill token，A→B→A 后实际复用 1,280、仅 prefill 92；容量压力淘汰后 A 仅保留 128、重新 prefill 1,244。共享 alias 在 A retire 后仍可复用；完整清空后 hit=0。冷／热／淘汰重算的贪心输出一致。协议 stop 正常释放；超时 prefill=0、取消时实际 prefill=512，活动序列均排空且其他 owner 的物理 KV 保留。受控探针不混入原 50 题数据或自然 U/D/C 发生率。

## 固定条件与计时范围

模型 revision `381fc969f78efac66bc87ff7ddeadb7e73c218a7`，权重 SHA256 `0c2f9e4daac78e72b24f7c054416232a523f0fd2aeb37653747d3c21f7dca078`，无量化，模型及 KV 均 F16，GPU 5/6/7 按层分区，非 tensor parallel。原生头文件／源码 275 项 Git blob 复核，8 份运行库本地 SHA256 记录。原采集 adapter 二进制保持，默认单序列行为保留。

资源核验后只使用 5/6/7，0–4 原任务保持，8/9 未使用。65,535,970,144 字节权重从持久副本复制到专属 `/dev/shm` 目录，复制中逐字节 SHA256 一致；本机磁盘读取使复制耗时约 1,189.5 秒。模型加载约 33.2 秒。这些是服务准备时间，单列，不计为某个缓存策略的任务时间或加速。

真实闭环使用先前测试题中的 logistic_holdout、ridge_validation、temporal_asof 三题；仍为已经查看过的开发数据，只做系统验收。六策略为 no_reuse、LRU、retire-first LRU、1 秒固定 TTL 软优先级、条件经验、GBDT。固定 TTL 在压力下将未到期块排在后面，过期后可按 LRU 淘汰，不硬阻塞就绪请求。两个预测策略仍使用固定 `F_U(3s)` 和相同分配规则。

每个策略从空池开始，三题同时提交；工具真实异步运行，模型单执行线程按实际 ready 时间 FCFS。没有把旧服务时长当新策略的时间，也没有用 sleep 充当工具耗时。调度器无工作时的 2ms 轮询是实测调度开销，纳入任务时间。工具仍为受限参数 API，实际子进程、2 线程、12GiB、240 秒超时；每题最大 6 次生成和 900 秒墙钟。每个工具结果必须进入后续真实模型输入，最终答案与产物再次对照冻结 reference。

三次重复，策略顺序每次循环平移两个位置，这是部分顺序平衡，不是完整 Latin square。固定种子／参数、容量和策略公式，不按结果挑轮次或改 horizon。模型无再训练，条件经验／GBDT 均只加载先前 40 训练题拟合的冻结模型。新的物理兼容 ID 保持独立；统计模型通过显式 domain adapter 映射兼容 guard，在新物理验收后复用同模型、tokenizer、F16、context 的粗粒度统计。这是声明过的统计迁移，不把不同后端的 tensor ID 当成可直接共享。

JCT 从共同提交时刻到最终答案通过独立检查，包含真实工具、模型、队列、输入检查、预测、策略和运行中的观测开销；保存单调时钟起止并独立重算。结束后的结果归档／流封口和模型加载另外报告。保留原有训练信息范围，未加入运算名称、未来工具耗时或最终结局；队列状态等训练未观测字段继续 unknown。当前 idle 特征从控制器完成原生证据核验并释放引用后计时，相对原生 release 有少量控制开销，是本次统计迁移的限制。

## 真实闭环结果

18 组全部完成，**54/54 次任务正确**；实际新增生成 181 次，其中受控 gate／prefill 19 次、真实闭环 162 次。下表按每策略相同三题×三轮的 9 次任务执行描述；三轮不是 9 个独立母题。

| 策略 | 平均 JCT / 秒 | P50 / 秒 | P95 / 秒 | 平均整批 makespan / 秒 | 每轮平均 prefill tokens |
|---|---:|---:|---:|---:|---:|
| 无复用 | 53.992 | 53.105 | 74.945 | 71.710 | 13,860.0 |
| LRU | 46.579 | 46.778 | 61.795 | 61.653 | 5,156.3 |
| 释放优先 LRU | **46.293** | 47.068 | 60.804 | **60.976** | 4,899.7 |
| 固定 TTL 软优先级 | 46.649 | 47.643 | 62.163 | 61.629 | 4,901.7 |
| 条件经验策略 | 53.108 | 47.036 | 97.563 | 81.377 | 4,900.0 |
| GBDT 策略 | 47.356 | 47.321 | 65.658 | 63.725 | 4,901.0 |

释放优先 LRU 的观测平均 JCT 相对无复用降低 **14.26%**；整批 makespan 约降低 14.97%。这说明当前真实系统中缓存复用有端到端价值，属于三母题开发验收的描述性结果，不是独立大规模性能结论。两种预测策略都没有优于强 LRU。相对释放优先 LRU，条件经验的配对平均差为 **+6.815 秒**，GBDT 为 **+1.063 秒**；不把没有增量的结果写成预测器带来的加速。

条件经验三轮平均 JCT 为 46.054／46.286／66.983 秒；释放优先 LRU 为 46.276／46.297／46.305 秒。条件经验第三轮 ridge_validation 的 compute 工具用时 **86.497 秒**，其中 worker 执行窗口 **82.607 秒**，该题完整 JCT **122.009 秒**，所有数值和失败／成功口径均保留，没有剔除重跑。对应三个模型请求的 native prefill 约 1.168／0.810／0.422 秒、decode 约 1.544／3.055／13.300 秒，长延迟主要落在工具 worker。该窗口包括读取 404MB 输入和真实五折拟合，未进一步细分 CPU、I/O 和调度等待，根因尚未隔离，不能据此认定预测算法导致了工具变慢。其他轮 ridge 工具也在约 10.7–40.9 秒之间波动。

所有预测策略／固定 TTL／释放优先 LRU 在每轮都命中 **8,960 tokens**，普通 LRU 为 8,704；主要策略间没有额外命中量。输入／生成中的 artifact ID 和文本 token 数有少量自然差异，故 prefill 总数不是完全相同。该 32 块、3 会话场景的预测排序空间很小，不能从仅有的毫秒级差值推断策略优势。

每轮平均模型 prefill 时间为无复用 16.921 秒、LRU 7.806 秒、释放优先 LRU 7.236 秒、条件经验 7.268 秒、GBDT 7.262 秒；decode 分别约 48.871／49.957／49.771／50.177／50.102 秒。由此可见，实际 prefill 已减少约 9.7 秒，但解码仍占大部分模型服务时间，端到端改善受其限制。不要把 token 降幅 64.6% 写成任务时间降幅。

条件经验每批预测合计约 0.35ms，GBDT 约 1.92ms，本例的条件经验长尾不能归因于这点推理 API 开销。完整来源保护、原生物理扫描、JSON 证据和调度成本仍处于 JCT 路径；CPU／磁盘与其他任务共享，未做独占性能声明。

独立进程重新 tokenization 并核对 181 个真实请求，复核 108 个工具结果进入后续输入、36 条 raw 流完整封口、全部实际物理并集／配额，以及最终答案和保存产物与 reference 一致。JCT 起止重算、请求与唯一预算 reservation 映射通过，未映射请求 0、预算外请求 0。适用最终回归 **219 passed / 1 deselected**；排除的是缺外部完整快照的 full_pinned_audit。最初相对 PYTHONPATH 导致的一项旧 shell 测试失败完整保留，绝对路径重跑及最终回归通过，未修旧 Codex 路线。

结论是：真实多 owner KV、受限工具与端到端测量闭环已经打通；本批支持使用释放优先 LRU 作为当前系统基线，暂未证明经验分布或 GBDT 排序有增量收益。下一阶段应预先固定 **24/32/64 块 × 3/6/10 会话**的压力矩阵，重新核对各请求能否入池；不挑最好容量。先补工具 worker 的读取、计算、CPU 时间和等待分项，再在同一线程／检查规则下完成交错重复。最终验证需新增冻结工作流／批次；如果更强压力下仍与 LRU 同动作，就不应继续仅调 GBDT 来追逐毫秒差值。共享队列、当前已就绪状态及重算成本可作为后续独立消融，先冻结模型与策略边界。
